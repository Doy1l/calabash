# Механики — как это работает

Код: `src/Core/` (чистая логика, без Unity) и `src/Unity/` (тонкий фасад).
Тесты: `tests/` — **105 штук, все проходят**.

## Как запустить проверку

```bash
dotnet run --project tests/Calabash.Tests.csproj
```

Никаких NuGet-пакетов не требуется — свой минимальный раннер.

## Почему логика отделена от Unity

Unity на этой машине установлен неполно (`Editor\Data\Managed` отсутствует,
Package Manager нет), поэтому headless-сборка проекта невозможна.
Но это и не нужно: **вся игровая математика не ссылается на UnityEngine**
и проверяется обычным `dotnet`. В Unity переезжает как есть.

Тест «фасад не тянет UnityEngine» следит, чтобы так и осталось.

## 1. Топливо = здоровье

`src/Core/Fuel/FuelSystem.cs`

Топливо постоянно убывает. Полоски здоровья нет — есть запас огня.

| Параметр | Значение | Смысл |
|---|---|---|
| `MaxFuel` | 100 | полный запас |
| `BurnPerSecond` | 2.2 | сгорает в секунду |
| `KillRefuel` | 17 | даёт одно убийство |

Состояния: `Normal` → `Hungry` (<40%) → `Starving` (<15%) → `Extinguished`.

Ключевое: **смерть — это не отдельная механика, а опустевшее топливо.**
Урон от воды, способности, горение — всё пишет в одно число.

## 2. Стадии тления

`src/Core/Decay/DecaySystem.cs`

Привязаны к **доле убитых**, а не ко времени: тело — это счётчик.

| Стадия | Доля убийств | Что с телом |
|---|---|---|
| `Ash` | 0–10% | подпалины на ладонях |
| `Smouldering` | 10–30% | трещины на предплечьях, дым |
| `Ember` | 30–55% | кисти обуглены |
| `Furnace` | 55–80% | рёбра светятся |
| `Bonfire` | 80–100% | лицо сгорело |

`StageProgress()` даёт 0..1 внутри стадии — для плавного перехода трещин
в шейдере, а не мгновенного щелчка.

## 3. Квота убийств

`src/Core/Combat/KillTracker.cs`

Механика голода: убил достаточно — прошёл уровень.
`RequiredKills = ceil(Population × RequiredFraction)`.

По умолчанию 48 жертв, нужно 85% → **41 убийство**.

## 4. Три концовки

`src/Core/Endings/RunDirector.cs`

| Условие | Концовка |
|---|---|
| Умер, никого не убив | `HeavenPure` — Рай |
| Умер после убийств (1-й раз) | `Limbo` — весы, вопрос |
| В Лимбо ответил «нет» | `HeavenRedeemed` — Рай через искупление |
| В Лимбо ответил «да» | возврат в бой, прокачка сохранена |
| Умер второй раз после возврата | `HellChained` — Ад, цепи |
| Выполнил квоту | `HellConqueror` — Ад, покоритель |

**Вторая попытка ровно одна.** Третьей нет — это проверено тестом.

## 5. Карточки прокачки

`src/Core/Progression/CardDeck.cs`

Всегда **три карточки**, даже если доступно меньше: нехватку добивает
карточка «Не брать» (`SkipCardId`). Отказ должен быть таким же осязаемым,
как выбор.

Взятая карточка не выпадает повторно. `PlayerStats` пересчитывает все
модификаторы с нуля при каждом добавлении — так невозможно накопить
рассинхрон.

## 6. Способности

`src/Core/Abilities/AbilitySystem.cs`

Каталог с уровнями 5 / 10 / 15. Пассивки (`Coals`) не попадают в список
активных способностей — это проверяется тестом.

Каждая способность стоит топлива: **сила всегда оплачивается горением**.

## 7. Уклонение

`src/Core/Movement/DodgeSystem.cs`

Ghostrunner-стиль. Идеальное уклонение в окне 0.12 сек даёт замедление
времени до 0.25×.

По дизайну это **единственный способ не получить урон от воды** — поэтому
вода и уклонение связаны через один `secondsUntilHit`.

## 8. Фасад для Unity

`src/Unity/CalabashGame.cs`

```csharp
var game = new CalabashGame();
game.StartRun(population: 48, requiredFraction: 0.85f);

// каждый кадр:
var ev = game.Tick(Time.deltaTime);
if (ev.EnteredLimbo) ShowScalesUI();
if (ev.RunFinished) PlayEnding(ev.Ending);
if (ev.DecayStageChanged) UpdateHandsShader(ev.NewDecayStage);

game.KillEnemy();               // убийство
game.ApplyWaterDamage(30f);     // вода
game.TryDodge(0.08f);           // уклонение
game.DrawCards();               // три карточки
```

`FrameEvents` — сводка изменений за кадр, чтобы MonoBehaviour не сравнивал
состояния вручную.

## Что нашлось при тестировании (реальные баги)

1. **Смерть от внешнего урона не замечалась.** `RunDirector.Tick` смотрел
   только на возврат `FuelSystem.Tick`, поэтому если героя добила вода
   между тиками, смерть проходила мимо. Теперь проверяется `IsDead`.
2. **Множитель отката работал наоборот.** Делил вместо умножения:
   прокачка «ускорение отката» замедляла его. Исправлено в двух местах —
   `DodgeSystem` и `AbilitySlot`.
3. **Лицо было утоплено в голову на 9 мм** (см. `tools/blender/`).
4. **Плашки лица не прилегали к сфере** — теперь Y считается из радиуса.

Это не гипотетические ошибки: каждую ловил тест, кроме третьей и четвёртой
(их поймал замер рендера).

## Открытые вопросы

1. **Сколько уровней** за забег — от этого число карточек в пуле.
2. **N% и население** — сейчас 85% от 48, надо подтвердить.
3. Прокачки **тратят топливо** или только враги? Сейчас способности тратят.
